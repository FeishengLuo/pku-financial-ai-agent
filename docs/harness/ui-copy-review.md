# 界面、文案与报告审查

2026-10-11，工作区 `D:\notes\pkuaiagent`，[PR #53](https://github.com/aeiou0123/pku-financial-ai-agent/pull/53)，继续使用 `industry-research-harness-20261010`。本轮从实际页面、源文件、输出报告和失败运行检查。使用 avoid-ai-writing 的文档模式审查文案，没有用审美词汇替代业务验收。

## 1. 发现的问题

- 模型教程的一步混入“通常最多请求256个输出token；OpenAI和MiniMax为思考预留2048个上限”。常用步骤不易读；额度细节应保留在说明中。
- 情景报告直接写内部状态 `constraint_conflict_valuation_withheld` 和 `None`，策略诊断报告直接打印区间JSON，研究底稿使用supports、forecast等英文分类。用户需要知道结果是否可用、数值来自什么参数。
- 输入框和标签页仍显示框架默认红色。旧CSS依赖没有实际匹配的元素；部分文字也仍使用框架字体。仅查看样式源文件不能证明显示效果。
- 盈利变化和策略诊断的输出没有完整登记到历史预览、概况及单项下载清单；文件已生成却不容易使用。
- 同一组参数成功后再次运行失败，旧诊断可能仍保留在会话里。失败记录缺少明确状态。
- 原文和模型说明经Markdown显示，可能解释其中的图片或HTML。研究材料应保留文字，而不是成为页面内容来源。

报告由本地结果生成，不让模型重写数值：回测列参数、区间、策略与基准、回撤；财务比率列披露日、报表范围、版本和期间；现金流估值列五年现金流与折现值，缺净债务时不计算股权价值；业务情景列年度预测、约束冲突与证据缺口。研究底稿保留支持、反证、未来陈述及来源定位。参数比较列出全部成功组与失败组，保留共同持仓区间的含义。

报告预览采用限定的标题、表格、引用和列表格式，全部正文转义。模型说明按文字显示。界面使用当前实际控件的样式入口，正文采用中文无衬线字体，焦点和选中态使用现有工作台配色；宽表只在自身区域滚动，可用键盘方向键查看。

盈利变化、现金流估值、情景、观点、回测与策略诊断均登记到成果预览。失败重跑清除本轮旧诊断，并保存失败状态；历史成功底稿不改写。

## 3. 差异与原因

从“解释程序怎么工作”改为“用户当前要做什么”；费用、来源和计算限制仍在对应位置。报告用参数和结果表表达金融口径，消除状态码和无意义空值，不更改回测或估值公式。数据缺口继续保留，不补零，不补日期，不把候选或用户假设写成已核事实。

本轮没有增加渐变、装饰卡片、虚构进度或泛化的智能宣传。样式必须在浏览器上看到，计算数字必须对应实际输出，失败状态必须能复查。
