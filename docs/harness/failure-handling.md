# 文件读取、失败提示与续取 Review

## 1. 问题与原文

多份材料中一份损坏时，整批读取原先会中断，页面只显示异常文字。用户很难判断是哪份文件、能否继续，以及已有结果是否保留。上传控件显示框架默认200MB，与本地20MB限制不一致。连接失败直接展示服务端说明，信息层级不清楚。

本机更新连接模块后，下游工具可能继续引用旧异常类型，导致中间批次失败后提前中断。静态文件一致不足以验证正在运行的进程。

## 2. 改写与最终行为

文件读取提示：“1个文件未能读取。请替换或移除这些文件后重新读取；尚未发送模型请求。”下方列文件、原因和处理方法；成功材料仍列出，但不默认采用缺文件的范围。移除失败文件后可重新读取并继续。财务读取另存新记录，问题清单和全部输入指纹可下载，既有成果保持原样。扫描、加密、损坏办公文档和CSV解析问题分别给出处理方法。

连接与执行失败显示短标题和操作建议，脱敏服务端说明按纯文字折叠展示。权限、账户额度、超时、上下文与输出上限各有说明。未知程序错误只显示类型，文件解析器的任意异常正文不显示。服务端或文件名中的标记不执行，也不自动加载图片。空密钥不会破坏脱敏文字。

上传控件与本地接收器均为每份20MB，合计60MB、最多10份。模块按依赖顺序刷新，检查旧API导入绑定，保留本次会话密钥。部分成功批次可缓存续取。

## 3. 差异与理由

提示围绕需要修正的输入、已保存的成果和下一步操作。读取失败会阻止分析；用户明确修正材料范围后才能继续。没有放宽来源、披露日期或16列财务校验，没有补数字、补日期或把摘录当作已核事实。金融计算和冻结技术题保持原方案。

## 4. 二次审查与实际证据

本轮使用Python、pytest、Streamlit AppTest、真实Chrome／Playwright、本机模拟HTTP服务。测试与浏览器收据、连续故障过程及部署包复核留在本机 `work/error_review_20261011/`；旧部署包在该目录另存。

浏览器检查覆盖混合好坏文件、失败清单与指纹下载、删除坏文件后的继续、手机问题表、产业材料登记阻断、损坏Excel、401／额度型429／503及成功重试。模型说明中的测试图片请求为零。回归检查原任务入口、无密钥样例、教程、键盘与手机入口、模型列表、本地体检，以及中间批次失败后继续尾部和只续取失败批次。实际服务商调用为零；这些记录不代表真实模型质量或真人业务效果。
