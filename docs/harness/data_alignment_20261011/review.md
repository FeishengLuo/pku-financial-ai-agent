## 3. 差异与理由：按比赛需求收敛

面向需要核对产业投资观点、财务变动或策略数据的研究者与团队同学。用户价值要落在“找到应读原件—核对证据与反证—明确兑现条件—保存可复查底稿”，而不是接入模型数量或聊天包装。

| 官方评分 | 当前可展示实现 | 仍需完成的实证与交付 |
|---|---|---|
| 问题与创新40分 | 日期与来源绑定、支持与反证、产能和投产约束、缺口保留、公告原件准备 | 用真实案例说明相对手工表格和直接问模型的增量；不能宣称原创金融模型或自动投资结论 |
| 效果与效率35分 | 确定性校验、失败恢复、计算结果、保存记录 | 真实模型候选逐项人工对照；记录漏项/错项、完成时间、请求/重试/token与费用；没有这些记录就不报业务准确率或省时比例 |
| 适用性与呈现25分 | 教程、合成样例、任务入口、失败建议、底稿下载 | 新用户无提示试用；独立机器启动；更新新版材料和连续录屏，避免旧视频演示另一版本 |
| 技术题额外15分 | 原冻结文件及此前独立复现记录 | 本轮未变动；不要把应用财务数据接入匿名因子流程或编造测试成绩 |

优先验证一个窄任务：一家公司的一条扩产增长论点，给定截止日，准备真实原件、支持和反证，再对照人工清单。财务研究与量化回测保持分开；量化先验数据口径、可得时间与成交假设，不让模型自填缺失值或优化已看的测试期。

建议实测表至少记录：案例和输入哈希、实际披露日、人工参考清单、候选正确/错误/遗漏数、引用定位问题、失败原因、人工修正次数、端到端耗时、模型配置、请求数、用量、服务商当期计费依据。按同一输入对照人工流程和直接问模型，公开失败样例。测试通过数不等于业务指标。
