## 当前入口与任务

仓库 https://github.com/aeiou0123/pku-financial-ai-agent ，测试分支 `industry-research-harness-20261010`。Windows运行根目录 `start_harness.bat`，默认 http://127.0.0.1:8510 。主入口 `harness_app.py`；表现与布局在 `src/harness/presentation.py`、`experience.py`，公告目录在 `catalog_ui.py`。先查看实际源文件，不以本文代替读取当前实现。

| 用户想做什么 | 输入与操作 | 输出 |
|---|---|---|
| 检查一个产业研究观点 | 准备公告原件，登记日期和公司/业务范围，确认计划，审查支持与反证 | 条件、引用、缺口和待核对事项；按需继续盈利兑现情景 |
| 整理并解释财务变化 | 原件提取候选，人工确认字段、单位、合并/母公司与期间，严格校验 | 16列事实表、两期变化与研究底稿 |
| 体检数据并测试策略 | 自己的CSV/XLSX，映射列，检查价格与面板，声明可得时间和交易假设 | 问题表、回测结果；按需做预先声明的参数诊断 |
| 找应读的公告 | 资料目录按公司/截止日/标题词检索 | 原件准备清单与目录溯源；不是全文证据或已核结论 |

辅助手段：教程与合成样例、模型与套餐说明、主动获取模型列表/测试连接、成果记录与下载、损坏材料/连接故障提示、失败批次续取。商业模型负责候选提取和审查草稿，自研模块负责来源/日期校验、状态、约束计算、确定性回测、恢复和导出。

## 设计目标

目标用户懂金融研究但未必懂API。先让他看清需要准备什么、当前做到哪一步、下一步是否收费、成果里哪些需自己确认。默认收起高级设置；给短教程和真正能点击完成的合成样例。按钮因条件不齐而不可用时，缺项应在按钮附近显示，不能靠用户猜。

沿用简单研究工具的排版：清楚的标题、标签、表格、足够的正文宽度与数字对齐。先解决窄屏、长文件名、宽表、加载和故障反馈；不要加入大面积渐变、装饰性图标卡片、悬浮动效、口号式“智能赋能”文案。颜色用于状态与操作，不能仅靠颜色区分待核/通过/失败。

可以调整任务导航、布局、间距、字体、文案和结果阅读层级；不要把三条任务混成聊天入口。材料要求、候选确认和真实披露日不是需要“简化掉”的步骤。对宽表可做列优先级/横向滚动，但来源、状态和关键单位必须能找到。成果概况后保留报告和逐项下载，不要只展示几个漂亮指标。

## 必须保留的行为

1. 合成、候选、待核、部分完成、已校验分开；合成演示不能使用真实公司事实措辞。
2. 日期、来源指纹、定位和公司/业务适用范围必须对应本次输入；财务16列校验、缺失值、更正及报表口径不放宽。
3. 标题命中不是论点成立，目录元数据不是全文；冲突不能自动选一个版本。未来产能、订单与价格仍是情景假设。
4. 金融公式、成交时点、因子可得时间、预算/有限重试与已保存结果不因改版改变。失败重跑不得显示上一轮成功为本次成果。
5. 不自动请求模型、列表或连接测试；显示实际请求范围，密钥只在会话内，换服务清除旧值，错误详情脱敏、按文字显示。
6. 私有源、商业数据、账号和真实密钥不能进入截图、公共提交或部署包。清单下载可给用户本地使用，不能发布完整商业目录。

## 改版后怎么验收

先用 `docs/harness/examples/` 合成材料走三个任务，再走无API样例和合成资料目录。自动检查运行 `python -m pytest tests -q`；页面检查用Chrome覆盖桌面与390px窄屏、键盘操作、来源确认/灰按钮原因、损坏文件移除后继续、连接失败与批次续取、关闭页面后历史底稿与空搜索。改标签时更新浏览器定位，但保留业务断言。

安装包由 `scripts/build_harness_package.py` 白名单生成，解压后独立检查启动页、样例、合成目录、计算和下载。只报实测结果，不把自动检查写成真人试用。不要改冻结07技术题或覆写旧正式01—07；新版正式材料需要同步重建、真实试跑和重录视频。

比赛截止和需求见[本轮对齐记录](data_alignment_20261011/review.md)。美化之后仍需拿真实案例对照人工清单、实测时间/费用并让新同学独立使用；这些证据决定“效果与效率35分”，无法由设计稿或测试通过数替代。
